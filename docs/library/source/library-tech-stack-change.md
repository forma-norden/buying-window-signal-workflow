# Tech Stack Change

> **What it targets:** Accounts that add, remove, or switch a tool in a workflow adjacent to the problem you solve.

## The logic

Tech stack change is one of the most underused triggers because it requires more interpretation than a job change or a pricing-page visit.

It is still worth using because it creates a better message angle:

- workflow friction
- consolidation pressure
- integration complexity
- replacement timing

## Tool options

| Tool | Purpose | Alternative |
| --- | --- | --- |
| Clay [enrichment / automation] | Stack enrichment and routing | Apollo.io [enrichment / prospecting] |
| Sales Navigator [prospecting] | Committee mapping | Manual LinkedIn review |
| HubSpot [CRM] | Track signal owner and status | Salesforce [CRM] |

## SOP

> **Step 1: confirm the change**
>
> - What changed?
> - How recent is it?
> - Is it adjacent enough to our workflow to matter?
>
> **Step 2: add context**
>
> - Which team likely owns the workflow?
> - Does the change create overlap, complexity, or evaluation pressure?
> - Are there supporting signals from hiring, visitor behavior, or leadership change?
>
> **Step 3: route**
>
> - High-fit + recent change -> outbound
> - Strategic account -> ABM + outbound
> - Weak-fit or old change -> monitor

## Message angle

Write to the operational implication, not the feature list.

Good angle:

> "Stack changes usually create one of two problems: more workflow complexity than expected, or a short window where teams are willing to replace adjacent process."

Bad angle:

> "Saw you use {{tool}} so we thought we'd pitch our features."

## Short template

> Subject: {{company}} stack shift
>
> {{first_name}} - looks like {{company}} has had a recent stack change around {{workflow_area}}.
>
> That usually creates a short evaluation window: either to simplify the process, or to fix the new friction the added tool creates.
>
> If it helps, I can send the checklist we use to identify whether the issue is tooling, routing, or data quality.

## Common mistake

Detecting the stack change correctly, then wasting it with product-led copy.

The signal earns you a workflow conversation. Use it.
